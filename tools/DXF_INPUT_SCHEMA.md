# TrainAiCad lower-level V4.9 DXF serializer (compatibility only)

**Production E2E** uses `tools/export_canonical_dxf.py` and
`tools/CANONICAL_INPUT_SCHEMA_V431.md`, not this lower-level CLI directly.
After canonical source/member validation, it writes one
`geometry_json/<CODE>.json` per part, PASS-only individual
`parts_dxf/<PASS_CODE>.dxf` with LINE/ARC/CIRCLE CUT primitives and one
all-code composite (`<JOB>_ALL.dxf` or `<JOB>_ALL_REVIEW_ONLY.dxf`).
See `tools/export_job_artifacts.py` for analytic bulge decomposition and
independent DXF read-back. The historical lower-level API described below
continues to behave exactly as its original tests require.

The serializer accepts **independently interpreted and verified** PDF drawing geometry. It never proves PDF dimensions, customer corrections, true unfold face order, manufacturing containment or Nobi. See [AI_ENTRYPOINT.md](../AI_ENTRYPOINT.md) and the active modular [core rule](../skills/lispcad/core/CAD_OUTPUT.md).

## Default and filenames

`python tools/export_dxf.py job.json out/` emits exactly ONE DXF, with all declared drawing codes in `job.parts` order from **top to bottom**, visible code annotation and >=10 mm layout-only geometric bbox clearance:
- All statuses PASS: `<JOB>_ALL.dxf`, production only if upstream Section 5 validations were actually executed.
- One or more PREVIEW/VIEWS_ONLY/FLAG codes: `<JOB>_ALL_REVIEW_ONLY.dxf` including *every* code; explicit global **REVIEW ONLY - NO CUT**; no misleading production file.

Part labels and review/status annotation are `TEXT` on generated **non-plot, non-cut `AI_META`** (not machining Layer 0). Code labels sit outside each part geometry bounding box; source views are also labeled. ALL actual geometric primitives remain on Layer 0. Exclude `AI_META` from CAM. Review-only composites are never cut, even if some individual clusters are accurate.

No individual DXFs or external JSON by default; an internal canonical-to-layout manifest is ALWAYS built and used for verification. `--write-manifest` requests its JSON copy. `--mode dual` explicitly requests historical V4.7 separate per-code + separated PASS/review composites + JSON manifest **only when the job contains PASS/PREVIEW and no VIEWS_ONLY**. DXF order and geometry must be derived from one shared canonical model, never solved twice.

## Input JSON

Job: `{"job_id":"JOB","parts":[PART_1, PART_2]}` in the source page-1/job-list order. Each part requires unique ASCII `code`, `material`, positive `thickness_mm`, `status:"PASS"|"PREVIEW"|"VIEWS_ONLY"`, `entities`, eight independently executed `checks` keys: `contour_topology`, `datum`, `feature_count`, `unfold`, `containment`, `bend_domain`, `material_rules`, `slot_semantics`.

- **PASS:** exactly one proved closed CCW `outer`, no flags, all critical checks actually PASS. Other checks PASS or genuinely N/A.
- **PREVIEW:** `preview_reason:"numeric_only_known_topology"`, at least one `flags` entry, one PROVED closed CCW outer, at least one genuinely estimated Magenta (6) geometric entity and adjacent Magenta `TEXT` with `role:"estimated_note"` on Layer 0. Only known topology with numerical uncertainty qualifies, e.g., explicitly user-authorized placeholder `2-Ø?`; NEVER production cut geometry.
- **VIEWS_ONLY:** `preview_reason:"separate_source_views"`, explicit nonempty `flags`, no forced joined flat. Every non-TEXT source entity must carry a unique per-projection `view_id` (e.g. `FRONT` or `SIDE`); multiple independent view groups must already be separated by at least 10 mm in either X or Y in the **part-local** geometry. View sources may have `role:"source_view"`; no fake closed outer is required. For checks whose full-flat evidence is missing, explicitly write `FLAGGED` instead of counterfeit PASS. The serializer automatically labels each source view on `AI_META`. Geometry remains clearly non-production.

All ordinary geometric `entities` are on Layer 0. Supported types: LWPOLYLINE (true bulge), CIRCLE (effective cut radius), POINT (actual point), LINE, ARC, and adjacent Magenta estimated warning TEXT. `role:"ordinary_point"` must be ByLayer; only explicit PIERCING+THROUGH HOLE `role:"through_piercing"` may be Green 3. Kegaki Red 1. Double bend LINEs DASHED. No arbitrary extra Layer-0 labels; `AI_META` identifiers/status notes are generated by the packager, never supplied as machining entities.

```json
{"job_id":"EXAMPLE","parts":[
  {"code":"A001","material":"SS","thickness_mm":2,"status":"PASS",
   "checks":{"contour_topology":"PASS","datum":"PASS","feature_count":"PASS",
             "unfold":"N/A","containment":"PASS","bend_domain":"N/A",

     {"type":"LWPOLYLINE","role":"outer","closed":true,
      "vertices":[[0,0,0],[60,0,0],[60,30,0],[0,30,0]]},

```

## Executed structural audit vs engineering proof

The writer reopens the saved DXF and checks mm header, Layer-0 geometry fingerprint including true polyline bulges, approved colors and POINT hierarchy, exactly ordered code labels on non-plot AI_META, per-code entity count, XY-only inverse-translation equality, source-view separation, top-down bbox clearance, and one global review label if applicable. It does **not** establish actual correctness of upstream PDF interpretation, true contour/containment, handwritten Nobi or customer approval. Full Section 5 checks and applicable drawing-specific regressions remain mandatory.

```bash
python -m pip install -r requirements.txt
python tools/export_dxf.py job.json out/ --gap-mm 10
python tools/export_dxf.py job.json out/ --write-manifest
python tools/export_dxf.py job.json out/ --mode dual  # ONLY when explicitly requested and VIEWS_ONLY absent
python -m pytest tests/ -q
```
