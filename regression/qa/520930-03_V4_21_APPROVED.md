# 520930-03 — V4.21 APPROVED PDF+CUSTOMER-DATA GEOMETRY PRESERVATION

**Approval date:** 2026-09-30  
**Mode:** calibration from PDF + customer raw DATA + user-declared approved DXF sample.

## FACT
For job 520930-03, customer raw DATA was supplied with the PDF. Direct audit against the approved sample showed that rebuilding some geometry from PDF dimensions introduced small drift even when overall dimensions closed.

User-approved universal workflow:
- whenever PDF + customer DXF DATA are present, production geometry must be extracted from DATA and cleaned/assembled according to PDF semantics rather than redrawn from PDF;
- this applies to all jobs, not only 646;
- 646 jobs are expected to have DATA by default; if DATA is missing, ask for it rather than proceed as PDF_ONLY.

## ROOT_CAUSE
The failed behavior mixed authorities: DATA was used as interpretation evidence while portions of geometry were recreated from PDF arithmetic. This breaks exact source-geometry provenance and can shift radii, reliefs, endpoints, centers and feature placement.

## APPROVED PRODUCTION LESSON
1. PDF + customer DATA => `PDF_DATA_RAW` unless user explicitly declares the DXF to be sample/approved/reference.
2. DATA is geometry authority; PDF is semantic/control authority.
3. Harvest and preserve source primitives/curves; clean and transform them. Do not redraw geometry already available in DATA.
4. Nobi/unfold determines relative placement of preserved faces.
5. Only explicit manufacturing/PDF canonicalization may replace source parameters; record each replacement.
6. Source reprojection is mandatory for unchanged geometry before PASS.
7. Customer/PDF delta thresholds do not legalize redraw residual.
8. 646 with missing customer DATA => `DATA_REQUIRED_MISSING`; ask for DATA and do not silently route to PDF_ONLY.
