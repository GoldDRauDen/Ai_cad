# 521005-05 — V4.31 E2E canonical completeness regression

**Status:** USER APPROVED / PUSH 2026-10-06.

## FACT

A clean V4.30 test run produced a syntactically valid/readable `521005-05_ALL_REVIEW_ONLY.dxf` but omitted proved feature members:

- `057862`: source contained multiple independent leader/callout groups; the runtime builder emitted only one Ø33 circle while group names survived only as annotation text.
- `057864`: source-proved hole centers were `Ø9 ×1`, `2-Ø6 ×2`, another independent `2-Ø6 ×2`, and `2-7キリ/Ø13 90°面取り ×2` = seven proved hole centers. The separate `8-R5` issue remained customer-pending, but the runtime builder emitted only one Ø9 circle.
- `057873`: bend domain logic correctly preserved bend-edge lengths 248/50 and positive bend-end offset no-slit behavior, but source `2-M8 (向側も有り)` was not instantiated as four M8 members; runtime DXF contained zero M8 primitives.

Audit of the failed runtime showed the serializer did not delete these features. The job builder never built a complete member-level canonical model: it wrote an ad-hoc subset directly to `ezdxf.modelspace()` and saved it. The so-called canonical review JSON was metadata only. QA counted selected codes/features and therefore allowed a false generic read-back PASS.

## ROOT_CAUSE

Primary:

`AI_WORKFLOW_ERROR + AI_IMPLEMENTATION_BUG`

Secondary:

`REGRESSION_COVERAGE_GAP`

`AI_MISREAD` is **not proved** merely because a semantic note/member was absent from the persisted ledger. Use `AI_MISREAD` only when direct trace evidence shows incorrect source interpretation.

There is no demonstrated `ROUTING_COVERAGE_GAP` for these three failures; HOLE/TAP/BEND routes existed.

## APPROVED LESSON

Normal production must enforce:

`SOURCE_FEATURE_GROUP -> SOURCE MEMBERS -> CANONICAL MEMBERS -> CANONICAL ENTITY IDs -> SAVED DXF ENTITY IDs`.

Hard equalities:

`PROVED_SOURCE_MEMBERS == PROVED_SOURCE_BACKED_CANONICAL_MEMBERS`

and

`CANONICAL_ENTITY_IDS == SAVED_DXF_LAYER0_ENTITY_IDS`.

A REVIEW_ONLY file is still forbidden from silently dropping a PROVED member. FLAG/uncertainty is local.

New jobs must use `tools/export_canonical_dxf.py`; direct ad-hoc `ezdxf.modelspace()` serialization from source interpretation is not the normal production path.

## REGRESSION CASE

Executable: `regression/tools/check_521005_05_v431.py`.

The executable deliberately uses **synthetic coordinates** so no hidden/sample coordinate can become future construction authority. It preserves only approved semantic/count facts:

- `057862`: four independent groups `2-Ø9`, `6-M6`, `6-Ø9`, `2-Ø9` = 16 proved circular operations, plus outer contour member. Negative fixture removes a subset and must fail `SOURCE_FEATURE_COMPLETENESS_FAIL`.
- `057864`: seven proved hole centers must survive while eight R5 members remain FLAGGED with no fabricated R geometry. Negative fixture retains only the Ø9 and must fail.
- `057873`: four M8 members and three bend members must survive; saved bend constituent lines re-read as lengths 248/248 and 50/50/50/50. No relief entity is introduced by the positive-offset 90° mechanism. Negative fixture removes the four M8 canonical members and must fail even though bends remain correct.

Positive fixture goes through `tools/export_canonical_dxf.py`, writes the review-only composite, stamps every Layer-0 canonical entity with stable `TRAINAICAD` XDATA `ENTITY_ID`, reopens the exact saved file, and proves canonical/saved entity-ID equality.

## NON-GENERALIZATION

The regression's fixture coordinates are not dimensions from `521005-05` and must never be used to reconstruct a future drawing. `248`, `50`, group quantities and the 90° relief behavior are retained only where already source/user-approved. Sample/reference DXF remains audit evidence, never a source of missing construction data.
