# 521001-19 — V4.26 APPROVED DXF physical-curve decoding regression

**Status:** USER APPROVED / DUYỆT 2026-10-03  
**Release:** V4.26  
**Scope:** production-wide DXF source/reference physical-curve decoding. No numeric Nobi, thread-pilot, material, tolerance, automatic-R table, or DATA<->PDF threshold changes.

## FACT

In job 521001-19, codes `057688 / 113` and `057689 / 114`, the PDF declares `2-R3` and `2-R1`.

The corresponding customer DXF DATA uses old-style `POLYLINE` geometry with nonzero vertex bulge. The relevant quarter-circle segments have `|bulge| ~= 0.41421356237`, so the physical geometry is ARC. Decoding the bulged segments yields the same R3/R1 families as the PDF.

A prior interpretation read only polyline vertex coordinates. Because the R3 and R1 arc endpoints have equal X/Y offsets, their straight chords visually resemble 45-degree `C3` and `C1`. That chord-only reading was wrong.

## ROOT_CAUSE

`AI_IMPLEMENTATION_BUG / AI_WORKFLOW_ERROR`.

The production rules protected output LWPOLYLINE bulges and physical representation equivalence, but input customer-DXF inspection lacked an explicit hard gate requiring old `POLYLINE`/`VERTEX` and `LWPOLYLINE` bulges to be decoded before topology/R-C classification.

## PROPOSED_LESSON — APPROVED

### DXF_PHYSICAL_CURVE_DECODE_BEFORE_CENSUS

Whenever a DXF participates as DATA/reference/audit source, decode entity containers into physical curves before Feature Census and semantic geometry classification.

### POLYLINE_BULGE_IS_ARC

For `POLYLINE` or `LWPOLYLINE`, a nonzero start-vertex bulge defines an ARC from that vertex to the next vertex. Do not substitute the endpoint chord. Closed polylines also require decoding the final-vertex -> first-vertex segment.

### PHYSICAL_CURVE_CENSUS

Retain per-segment source provenance and physical type, including bulge, endpoints and arc center/radius/sweep when applicable.

### BULGE_ARC_NOT_CHORD HARD GATE

If source `|bulge| > CAD numerical zero`, production FAIL if the physical census/canonical source-preservation layer classifies that source segment as LINE or if source reprojection checks only endpoints/bbox.

### R/C CLOSURE AFTER DECODE

Only compare PDF R/C semantics against DATA/reference R/C geometry after the DXF physical curves are decoded. Do not declare `SOURCE_CONFLICT` from a chord-only view of a bulged polyline.

## REGRESSION_CASE

Executable guard: `regression/tools/check_521001_19_v426.py`.

The executable creates and reopens synthetic old `POLYLINE` and `LWPOLYLINE` cases, proves quarter-circle bulges decode to ARC with expected R3/R1 radii, proves a closed last->first bulged segment is not skipped, and verifies V4.26 router/release wiring plus saved-DXF read-back.

## NEGATIVE REGRESSION

FAIL if any of the following recurs:

- endpoint/chord inspection is used to classify a bulged `POLYLINE`/`LWPOLYLINE` segment as chamfer/LINE;
- old `POLYLINE` `VERTEX` group-42 bulge is ignored;
- the final->first segment of a closed polyline is omitted;
- physical source/reprojection comparison checks vertices or bbox but not ARC center/radius/sweep;
- a PDF/DATA `SOURCE_CONFLICT` is reported before decoding source physical curves;
- a bulged source arc is lost while the output still receives `PRODUCTION PASS`.
